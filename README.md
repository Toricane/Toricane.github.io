# Prajwal Prashanth’s portfolio

Built with [Quartz 5](https://quartz.jzhao.xyz/) and deployed as a static site on GitHub Pages at [prajwal.is-a.dev](https://prajwal.is-a.dev).

## Structure

```
content/                  # Markdown pages + assets (the CMS)
  index.md                # Home introduction + curated narrative chapters
  coverflow.md            # Home photo reel
  projects|awards/
  assets/
    tab-panels/           # Full-size entry images
      small/              # 800px-wide gallery / coverflow thumbs
      preview/            # 256px-wide timeline thumbs
    icons/                # Inline bio link icons
site-plugins/portfolio/   # Site UI, RSS, Markdown endpoints + agent search
scripts/                  # Image variants, git-hook installer + output checks
.githooks/pre-commit      # Runs npm run images before commit
quartz.config.yaml        # Site config, theme, plugins
.github/workflows/pages.yml
```

There is no separate content sync step or manually maintained collection data file. Collection listings, Markdown endpoints, and the agent search index are generated by the portfolio plugin from the published Markdown content and frontmatter.

## Home page

The homepage is a finite scrolling narrative: an introduction and curated photo
reel, a compact selected-project overview, then authored project chapters
(currently cell-safe before JARVIS). `## More selected work` places contribution
and result summaries for selected projects without a full chapter. Community work,
smaller tools, hackathons, milestones, and contact follow. The introduction fills
the first desktop viewport; mobile follows its content height.

Up to six projects marked `significance: spotlight` appear automatically, newest
first. Their first `## Gallery` image supplies the card image; entries without
images stay text-only. Contribution and result summaries come from the project
entries. The remaining narrative and hero facts are curated in `content/index.md`.

The timeline spans the overview heading, cards, and archive links, with full-width
detailed stories below, and moves into the left margin on wide desktops. The
Projects and Awards links share their row equally, without reserving a future section.

Project totals, hackathon builds, and hackathon awards are calculated from content.
Tag relevant award entries `Hackathon` so placements, side challenges, and
honourable mentions are included, rather than counting only first-place projects.

The newsletter is resolved from Substack at build time, with a last-good feed and
verified snapshot covering upstream failures. Its home preview is only rendered
when the latest post is within four calendar months of the build. A new post
requires a site rebuild. The browser does not fetch an external RSS proxy.

For every content change, use the [home-page maintenance guide](site-plugins/portfolio/HOME-MAINTENANCE.md)
to decide whether the curated home page needs an edit. Most new entries require
no home-page change: selection, counters, timeline data, and derived summaries
update automatically. Technical details live in the [plugin documentation](site-plugins/portfolio/README.md).

## Update content

- Home copy, section descriptions, chapter order, image alt text, and CTA labels live in [content/index.md](content/index.md). Move a whole `##` section to reorder it; edit the standalone final link to change its CTA. Image-only paragraphs automatically get an expansion icon and keyboard support. See the [editing example](site-plugins/portfolio/HOME-MAINTENANCE.md#quick-editing-reference).
- Edit Markdown under `content/`.
- Add a project in `content/projects/`, a hackathon project in `content/projects/` with the `hackathon` tag, or an award in `content/awards/`.
- Put the full image in `content/assets/tab-panels/` and reference it in `## Gallery`. Collection pages are `/awards/` (trailing slash); entries are `/awards/some-slug` (no slash).
- Missing `small/` and `preview/` files are created on commit (after `npm run hooks`), or anytime with `npm run images`. Existing variants are left alone unless you run `npm run images -- --force`.
- Home coverflow: edit `photos` in `content/coverflow.md`. Optional `link` opens an entry modal (e.g. `/awards/class-valedictorian`); omit `link` for a full-image lightbox.
- Hackathon projects use `content/templates/hackathon.md` and a quoted `when: "YYYY/MM"` for a completed month-only timeline event. Existing hackathon URLs redirect to their project pages.
- Project pages may still contain `[Replace with: …]` prompts — replace only when you have verified copy. The build hides prompts, template example links, and empty section headings until actual content is added.
- Check whether the change affects an authored home claim, selected milestone, photo caption, or curated story. Update only the affected copy following the [maintenance guide](site-plugins/portfolio/HOME-MAINTENANCE.md); do not copy project totals or the selected-project list into `content/index.md`.

### Image sizing convention

| Surface                    | Variant               | Size       |
| -------------------------- | --------------------- | ---------- |
| Gallery cards + coverflows | `tab-panels/small/`   | 800px wide |
| Timeline thumbs            | `tab-panels/preview/` | 256px wide |
| Lightbox / expanded        | `tab-panels/` (full)  | original   |

The plugin rewrites paths automatically; keep frontmatter and gallery Markdown pointed at the full image. Variants are **not** generated during `npx quartz build` or GitHub Pages CI.

Install the pre-commit hook once:

```sh
npm run hooks
```

That copies [`.githooks/pre-commit`](.githooks/pre-commit) into `.git/hooks/` so each commit fills in missing thumbs and stages them.

## Access for AI agents

Every published page has a static Markdown version. Remove a trailing slash and
append `.md`: `/` → `/index.md`, `/projects/` → `/projects.md`,
`/awards/` → `/awards.md`, and `/projects/cell-safe` → `/projects/cell-safe.md`.
Generated folder/tag pages and legacy aliases are included. Named `index.md`
and `.html.md` forms also work; bare `.md` filenames are not generated. Assets
and unknown paths do not receive Markdown equivalents.

Markdown uses root-relative links for same-site pages and images. Collection
listings include dates, highlight level, tags, and affiliation. All exported dates
use `YYYY-MM`; source frontmatter retains its existing `YYYY/MM` month-only or
`YYYY-MM-DD` range schema.

`/llms.txt` contains a brief description of Prajwal and the site, URL/search
instructions, and five links: About, Projects, Awards, Resume, and Search index.
`/search-index.json` contains cleaned text and metadata for local agent search.
Agents match terms locally and follow each result's `markdownUrl`; there is no
server-side query endpoint. Both files are generated during the normal build.

Every Markdown page includes Home, Projects, Awards, and Resume menu links.
Resume links to `/resume/resume.md`, which is provided by the separate resume project.
This build does not fetch or generate resume content; output checks allow that
separately managed endpoint.

See the [portfolio plugin documentation](site-plugins/portfolio/README.md) for
the search schema, export behavior, and verification commands.

## Develop

Requires Node.js 22 or newer.

```sh
npm install
npx quartz plugin install --from-config
npm run hooks
npx quartz build --serve
```

If you change the local plugin source:

```sh
npm run build --prefix site-plugins/portfolio
npx quartz plugin install --from-config
```

Then restart the running serve process so it loads the rebuilt plugin. Content-only
Markdown edits are picked up by the existing preview's watcher.

Checks and production build:

```sh
npm run check
npm run typecheck --prefix site-plugins/portfolio
npx tsx --test site-plugins/portfolio/src/*.test.ts
npx quartz build
node scripts/check-markdown-output.mjs public
```

## Deploy (GitHub Pages)

Workflow: [`.github/workflows/pages.yml`](.github/workflows/pages.yml) builds on push to `v5`, checks Markdown endpoint coverage, discovery links, internal Markdown links, and the search index, then deploys `public/`. CNAME is `content/CNAME` (`prajwal.is-a.dev`). Commit generated `small/` and `preview/` files; the Action does not resize images.

You can do this in GitHub **before** any push:

1. Repo **Settings → Pages → Source** = **GitHub Actions** (not “Deploy from a branch”).
2. Custom domain should already be `prajwal.is-a.dev` (matches `content/CNAME`).

When you are ready to cut over (after content edits):

3. Locally verify: `npm run check` and `npx quartz build`, then spot-check `/`, `/awards/`, coverflow lightbox, and an entry modal.
4. Push the `v5` branch to `origin` (this repo’s deploy branch).
5. Confirm the **Deploy portfolio** Action succeeds.
6. Confirm [prajwal.is-a.dev](https://prajwal.is-a.dev) serves the new build.

`main` may still hold the older Astro site until you fully cut over. Do not push until content is ready.

## Keeping Quartz up to date

Remote `upstream` points at [jackyzha0/quartz](https://github.com/jackyzha0/quartz) (`v5`).

There is **no automatic sync**. Periodically:

```sh
git fetch upstream
git merge upstream/v5
# resolve conflicts carefully around quartz.config.yaml and site-plugins/
npm install
npx quartz plugin install --from-config
npm run hooks
npm run check
npx quartz build
```

Prefer keeping customizations in `site-plugins/portfolio/` and `content/` so upstream merges stay small. A scheduled PR workflow can be added later if needed.
