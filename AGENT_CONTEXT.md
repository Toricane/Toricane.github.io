# AI Agent Context: prajwal.is-a.dev Portfolio

This document provides architectural, stylistic, and operational context for any AI agent assisting with the `Toricane.github.io` repository.

## 1. Project Overview & Architecture
*   **Tech Stack**: [Astro](https://astro.build) static site (`src/`) with vanilla CSS (`styles.css`) and vanilla JS client islands (`src/scripts/`). **NO** React/Vue/Tailwind.
*   **Production output**: `dist/` (deploy via `.github/workflows/pages.yml`).
*   **Data-Driven Content**: Portfolio content is authored as Markdown in `src/content/` (Obsidian-friendly), validated at build time via Astro Content Collections.
    *   **Projects / hackathons / awards**: one `.md` file per entry under `src/content/{projects,hackathons,awards}/`
    *   **Hero**: `src/content/hero/intro.md` (custom `[{icon} label](url)` syntax via `compileHeroTagline`)
    *   **SEO**: `seo.json` → `src/components/SeoHead.astro` + `@astrojs/sitemap`
    *   **Colors**: `colors.json` (generated by `scripts/update_colors.py` from image paths in content frontmatter)
    *   Never hardcode portfolio items in Astro pages; add or edit content notes and rebuild.
    *   Root `data.json` is **generated** from Markdown on each sync (`scripts/export-data-json.mjs`); do not edit it by hand.
*   **Module Structure**:
    *   JS components in `src/scripts/components/`.
    *   `src/scripts/boot.js` hydrates from inlined `window.__SITE_RUNTIME__` (production).
    *   `src/lib/buildPortfolio.ts` aggregates collections into the legacy `Portfolio` shape for renderers.
    *   `src/content.config.ts` defines collection loaders and Zod schemas (Astro 6).
    *   `styles.css` is monolithic with CSS variables at the root.

## 1b. Astro build & dev (CRITICAL)

| Command | Action |
|---------|--------|
| `npm run dev` | `sync-public` + Astro dev server (HMR) |
| `npm run build` | `sync-public` + static `dist/` |
| `npm run preview` | Preview production `dist/` |
| `npm run new:project -- "Title"` | Scaffold `src/content/projects/<slug>.md` |

See **[CONTENT.md](CONTENT.md)** for the full authoring workflow.

*   **Static assets**: `node scripts/sync-public.mjs` copies `assets/`, `connect4/`, favicons, `CNAME`, `robots.txt`, `llms.txt` → `public/`; syncs `colors.json` and `seo.json` → `src/data/`; runs `export-data-json.mjs` → root `data.json`.
*   **Client JS**: `src/scripts/boot.js` hydrates tabs, coverflow, hash nav, widgets (deferred import).
*   **Sitemap**: `@astrojs/sitemap` → `dist/sitemap-index.xml`; `robots.txt` points to it.
*   **Runtime data**: Production uses inlined `__SITE_RUNTIME__`; do not fetch `data.json` on production builds.

## 2. Design System & Aesthetics (CRITICAL)
*   **Theme**: Dark/Midnight glassmorphism; light theme via `theme.js` / `[data-theme="light"]`.
*   **Animations**: CSS `box-shadow` glows, `.nav-highlight`, `.linkedin-highlight` for `?tap=true`.
*   **Responsive**: Mobile-first.

## 3. Notable Components & Update Rules
*   **Coverflow**: Images with `face: true` in content frontmatter. Run `python scripts/update_colors.py` after adding face images.
*   **Tabs & Timeline**: Built from `buildPortfolio()` → `renderProjectsHtml` / `renderTimelineHtml` at build time.
*   **Navigation**: Hash routes `#projects/slug`, `#awards/slug`, etc. Slugs from `slugify()` in `src/scripts/utils/data.js` (match `data-slug` on rendered HTML).
*   **Hero tagline**: Edit `src/content/hero/intro.md`.
*   **Icons**: Edit `src/scripts/icons.js`; run `npm run build`.

## 5. Development Rules
1.  **Content**: Edit `src/content/**/*.md`; run `npm run build` or `npm run dev`.
2.  **CSS**: Use existing variables; test overflow on animations.
3.  **Connect Four**: `connect4/` — separate URL, in sitemap.
